RENCANA TABEL UNTUK MASING-MASING MODUL VIEW
===========================================

Dokumen ini berisi rencana tabel backend berdasarkan struktur view dan data dummy pada frontend.
Status: usulan awal, bisa disesuaikan saat implementasi API/backend final.

==================================================
0. MODUL UMUM MANAJEMEN AKSES DAN MASTER
==================================================

A. Tabel: companies
Tujuan:
- Menyimpan master perusahaan.
Kolom utama:
- id (bigint, PK)
- code (varchar, unique, nullable)
- name (varchar)
- kota (varchar)
- bidang (varchar, nullable)
- alamat (text, nullable)
- telepon (varchar, nullable)
- npwp (varchar, nullable)
- status (enum: aktif, trial, nonaktif)
- modules (integer, default 0)
- color (varchar, nullable)
- is_active (boolean, default true)
- created_at
- updated_at

B. Tabel: roles
Tujuan:
- Menyimpan master role sistem.
Kolom utama:
- id (bigint, PK)
- name (varchar)
- short_code (varchar, nullable)
- group_name (varchar, nullable)
- color (varchar, nullable)
- is_active (boolean, default true)
- created_at
- updated_at

C. Tabel: modules
Tujuan:
- Menyimpan master modul/menu sistem.
Kolom utama:
- id (bigint, PK)
- key (varchar, unique)
- label (varchar)
- description (text, nullable)
- group_name (varchar, nullable)
- icon (varchar, nullable)
- allowed_roles (json, nullable)
- allowed_actions (json, nullable)
- is_active (boolean, default true)
- created_at
- updated_at

D. Tabel: users
Tujuan:
- Menyimpan akun pengguna aplikasi.
Kolom utama:
- id (bigint, PK)
- company_id (bigint, FK -> companies.id)
- role_id (bigint, FK -> roles.id)
- name (varchar)
- email (varchar, unique)
- phone (varchar, nullable)
- password (varchar)
- status (enum: aktif, nonaktif)
- last_login_at (datetime, nullable)
- created_at
- updated_at

E. Tabel: company_module_permissions
Tujuan:
- Menyimpan matrix hak akses per perusahaan, per modul, dan per role.
Kolom utama:
- id (bigint, PK)
- company_id (bigint, FK -> companies.id)
- module_id (bigint atau varchar key, FK -> modules.id / modules.key)
- role_id (bigint, FK -> roles.id)
- allowed (boolean)
- created_at
- updated_at

Catatan umum:
- Struktur di atas mengikuti model backend yang sudah ada: Company, User, Module, dan CompanyModulePermission.
- Jika ingin menyimpan riwayat pindah perusahaan user, bisa tambahkan tabel `user_company_histories`.

==================================================
SARAN UMUM RELASI DAN IMPLEMENTASI
==================================================
- Semua tabel transaksi sebaiknya memiliki `company_id` jika aplikasi mendukung multi perusahaan.
- Untuk kebutuhan soft delete, pertimbangkan kolom `deleted_at` pada tabel master/transaksi.
- Untuk kecepatan laporan, modul Finance, Accounting, QC, dan Audit Log cocok memakai tabel summary bulanan.
- Untuk Accounting, model terbaik adalah memisahkan header jurnal dan detail jurnal, bukan satu tabel campur debit/kredit.
- Untuk Audit Log, kolom perubahan lebih aman disimpan dalam JSON agar fleksibel.
