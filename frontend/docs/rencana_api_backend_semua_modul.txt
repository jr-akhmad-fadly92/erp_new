RENCANA API BACKEND - SEMUA MODUL ERP
=====================================

Tujuan:
- Menjadi kontrak API awal antara frontend dan backend.
- Backend tinggal menyesuaikan endpoint, payload, dan format response yang diminta frontend.

Catatan umum:
- Base URL: /api
- Format response disarankan konsisten agar frontend mudah integrasi.
- Semua endpoint private wajib pakai Bearer token kecuali login.

--------------------------------------------------
1) STANDAR RESPONSE DAN ERROR
--------------------------------------------------

A. Response sukses (single object)
{
  "success": true,
  "message": "ok",
  "data": { ... }
}

B. Response sukses (list + pagination)
{
  "success": true,
  "message": "ok",
  "data": [ ... ],
  "meta": {
    "page": 1,
    "per_page": 20,
    "total": 120,
    "last_page": 6
  }
}

C. Response error validasi
{
  "success": false,
  "message": "Validation failed",
  "errors": {
    "field_name": ["field is required"]
  }
}

D. Response error umum
{
  "success": false,
  "message": "Unauthorized"
}

RENCANA API BACKEND SEMUA MODUL (KONTRAK UNTUK TIM BACKEND)
=============================================================

Tujuan dokumen:
- Menjadi acuan endpoint API yang dibutuhkan frontend saat ini.
- Memudahkan tim backend menyesuaikan route, payload, dan response data.
- Menyeragamkan pola response agar integrasi lebih cepat.

Base URL:
- /api
Contoh:
- http://localhost:8000/api

==================================================
A. STANDAR RESPONSE
==================================================

1) Response sukses (list)
{
  "success": true,
  "message": "ok",
  "data": [ ... ],
  "meta": {
    "page": 1,
    "per_page": 20,
    "total": 200,
    "last_page": 10
  }
}

2) Response sukses (detail/create/update)
{
  "success": true,
  "message": "ok",
  "data": { ... }
}

3) Response gagal validasi (422)
{
  "success": false,
  "message": "validation error",
  "errors": {
    "field_name": ["pesan error"]
  }
}

4) Response gagal umum
{
  "success": false,
  "message": "error message"
}

Catatan:
- Frontend saat ini membaca body JSON dan message/error.
- Gunakan header Bearer token untuk endpoint private.

==================================================
M. CATATAN IMPLEMENTASI BACKEND
==================================================

1. Authorization:
- Endpoint admin-only: /users, /permissions, /audit-logs, /companies (sesuaikan policy).
- Endpoint modul mengikuti permission matrix company_module_permissions.

2. Consistency naming:
- Frontend saat ini campuran snake_case dan camelCase di data dummy.
- Disarankan backend pakai snake_case di API payload.
- Jika frontend tetap pakai camelCase, gunakan transformer di frontend atau backend resource.

3. Pagination:
- Semua endpoint list sebaiknya support page, per_page, search, sort.

4. Export:
- Endpoint export boleh return file stream langsung (CSV/PDF) atau return signed URL download.

5. Multi-company:
- Selalu hormati company_id aktif dari user/token.
- Hindari user mengakses data company lain kecuali Super Admin.

6. Logging:
- Audit log disarankan otomatis dari middleware/service layer, bukan hanya dari request manual.
